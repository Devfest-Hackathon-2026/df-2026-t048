# 英語対応（2026-11-08）

> 最新指示でアプリの表示・AI応答は日本語／英語、OCRは日本語／Latinに限定。中国語・韓国語はポスターで案内する。[変更記録](app-languages-ja-en.md)。

## 今回の範囲

ユーザー指定により、対応言語は日本語と英語。端末の優先言語から初期表示を選び、未対応言語は英語へフォールバックする。「設定 → 言語」で端末に合わせる／日本語／Englishを選択でき、端末内に選択を保存する。ログイン不要で、クラウドバックアップには言語設定を含めない。

カメラの注意、基本チェック、投稿準備、候補の確認、ぼかし・黒塗り・図形・ブラシ編集、保存と共有、設定、位置情報、施設ルール詳細のアプリ文言を英語化。iOSの権限説明にも英語・日本語のリソースを追加。OSの権限ダイアログや保存先の画面はOS側の言語設定に従い、アプリ内の言語指定とは独立する場合がある。Google Mapsの地名など、SDKが描画する地図内容の言語もアプリ文言の翻訳対象外。

## 美術館・旅行先での扱い

- 登録施設の撮影／SNS公開／商用利用の構造化された条件を翻訳する。「可／不可／条件付き／未確認」の区別を保ち、未確認を許可と表示しない。
- 施設名・イベント名・対象エリア・規約の原文・根拠の抜粋・利用者の文章・認識した文字は元の言語を保持する。原文の自動翻訳機能は今回含まない。写真・OCRをクラウド翻訳へ送る処理は追加しない。
- 施設ルールは、申請・承認された自前の登録施設が対象。海外を含む任意の美術館のルールをGoogle Mapsから自動収集する機能ではない。
- 外国語の非表示ワードは文字列で登録可能。英語のconfidential／under embargo等と、+付き国際電話番号も確認候補にする。機密や違反を断定せず、最終確認は利用者に求める。

## 文字認識・端末内AI

静止画は既存のGoogle ML Kit日本語OCRとLatin OCRを端末内で順に実行。同じ文字とほぼ同じ矩形だけを重複除去し、読み取り内容が違う候補は残す。撮影中は日本語・Latinをフレームごとに交互実行し、1フレームの処理負荷を増やさない。表示言語が英語でも、日本語を検査対象から外さない。

インストール済みのGemmaを使う場合は表示言語に合わせて短い質問の言語を指定する。質問の言語・認識精度を保証するものではない。既にチェックしたAIの自由文や投稿内容は、言語変更時に翻訳し直さない。投稿文に適用する既存の非表示マーカーは「［非表示］」のまま維持する。

ML Kitの対応文字体系は[Google公式](https://developers.google.com/ml-kit/vision/text-recognition/v2/languages)を参照。今回追加したUI翻訳と、全言語の文字認識への対応は別のもの。中国語・韓国語などのUI・専用OCRモデルは追加しない。

## 構成・追加方法

`postcheck/lib/l10n/en.json`にアプリ作成文言の英訳を管理し、`python3 tool/generate_translations.py`で`english.dart`を生成する。翻訳はローカルで完結する。現行ドメインAPIが持つ日本語メッセージを安定したキーとして扱い、UI境界で`AppText`／`tr`が翻訳する。原文・ユーザー入力は通常の`Text`を使う。動的文言は文全体のテンプレートとし、施設名・ワードの引数を翻訳しない。翻訳してよいアプリ内状態ラベルの引数のみ明示的に指定する。

`domain`／`application`にはFlutterのLocale・BuildContextを持ち込まない。Gemmaの出力言語は構成時のコールバックで渡す。

## 検証

- 言語変更・選択の保存・再起動後の復元・端末言語追従・未対応言語の英語フォールバックをWidgetテストで確認。
- 英語の確認→選択→修正→再チェック→共有前プレビューを390pxと320px（文字拡大あり）でテスト。
- 英語の施設条件と原文保持を320px・文字拡大でテスト。原文や登録ワードが翻訳キーと同じ文字列でも、引用内容を翻訳しないことを確認。
- 英語の機密候補・+44／+1形式・メールの検出範囲、通常の日付や数字を国際電話として拾わない例をテスト。
- OSの保存先／SNSでの英語表示、実施設の外国語原文、多言語混在の実写、英語でのGemma応答品質は実地検証が必要。
