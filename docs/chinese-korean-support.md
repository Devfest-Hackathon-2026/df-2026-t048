# 中国語・韓国語対応（2026-11-09）

> **最新方針：** 2026-11-09の最新ユーザー指示により、モバイルアプリの中国語・韓国語対応を撤去。UI・AI応答・施設ルールの案内は日本語／英語、OCRは日本語／Latinに限定する。中国語・韓国語はポスターの案内で扱う。既存の施設原文・翻訳データを破壊しないため、管理Web・API・共通契約の保存形式は保持する。 以下は追加当時の履歴。[撤去の範囲と検証](app-languages-ja-en.md)。

> 追加対応：施設の具体的な条件・対象エリア・確認済み翻訳と、言語別の非表示マーカー・中国語／韓国語の告知キーワードは[施設ルールの多言語説明V18](multilingual-venue-rules-v18.md)を参照。以下は言語追加時点の記録。

ユーザーの「中国語、韓国語も対応」「アプリの方」の指定により、Flutterアプリへ中国語（簡体字）と韓国語を追加。管理Webは今回の対象外。

## 対応範囲

- 設定 → 言語から日本語／English／中文（简体）／한국어／端末に合わせるを選択。選択は端末内へ保存し、画面遷移を維持して反映する。
- 端末の優先言語から初期表示を決定し、未対応言語は英語。中国語の地域・文字体系の違いは簡体字UIへ集約する。繁体字UIは今回含まない。
- カメラ、投稿準備、候補確認、ぼかし・黒塗り・図形編集、保存・SNS共有、設定、位置、施設条件など、既存の英語カタログと同じ457文言を両言語へ翻訳。
- 施設の「許可／禁止／条件付き／未確認」を区別し、未確認を許可扱いしない。施設名・規約原文・対象エリア・登録ワード・OCR・投稿文は元の文字列を保つ。
- インストール済みGemmaへの質問言語指定を追加。原文引用・blockId・座標禁止などの契約は維持する。チェック済みのAI自由文は言語変更時に再翻訳しない。応答言語の遵守や品質は保証しない。
- iOSの権限説明をzh-Hans／koのInfoPlist.stringsに追加。OSダイアログやSNS、地図SDK内の表示言語は各OS・アプリ側の設定に従う場合がある。

## 文字認識

既存の日本語・Latinに中国語・韓国語のML Kitモデルを追加。iOS CocoaPodsは既存と同じGoogleMLKit 9.0.0系、Androidは同梱版16.0.1へ固定。静止画は4モデルを順次実行し、同一の文字と重なる矩形を重複除去する。異なる読み取り候補は保持する。ライブは1フレーム1モデルで4モデルを交代し、同時実行を増やさない。表示言語に関係なく4文字体系を検査する。

モデル同梱に伴いアプリ容量は増える。静止画の処理時間やライブの各文字体系の更新間隔への影響は、実機で別途計測が必要。今回、実写での認識精度は未検証。中国語・韓国語専用の機密キーワード辞書は追加せず、既存の連絡先ルール・読み取った文字の確認・利用者の登録ワードを使用する。

SDKの追加方法はGoogle公式の[iOS手順](https://developers.google.com/ml-kit/vision/text-recognition/v2/ios)・[Android手順](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)を確認した。クラウド推論やクラウド翻訳の経路は追加していない。

## 保守

`postcheck/lib/l10n/zh.json`／`ko.json`が翻訳元。`python3 tool/generate_translations.py`でDartカタログを生成する。生成時に英語とのキー一致・空文言・プレースホルダーの一致を検証する。動的引数のうちアプリの状態ラベルだけを翻訳し、原文や登録ワードは翻訳しない既存の仕組みを継続する。
