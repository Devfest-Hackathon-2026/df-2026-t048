# iwase管理画面と既存APIの統合（V16）

更新：2026-11-09。対象は `origin/iwase` の `b0778e3` と、mainのモバイル版 `54595c7`。申請画面・運営画面のデザインを取り込み、接続上の問題を修正した。

## 確認と修正

- **運営の権限**：一覧の閲覧権限が下書き変更にも使われていた。Goで操作ごとに判定し、運営による施設作成・他組織の保存・代理申請・取り下げを拒否。別組織の審査・差し戻し・公開停止は維持。
- **自動保存の競合**：自動保存中の申請や編集で、二重作成・古い保存応答による未保存状態の消失が起き得た。要求を直列化し、保存中の追加編集は次の保存へ引き継ぐ。保存状態と失敗を表示し、入力を保持する。
- **参考画像**：新しい `sourceImage` を暗号化された施設データへ保存できるよう、Web・共通Dart契約・Goを統合。氏名・連絡先・参考画像・内部申請名を一般公開APIから除外。画像は審査用であり、画像照合モデルやクラウドAIには渡さない。
- **画像の制限**：PNG/JPEG/GIF、18KiBまで。Goでbase64・実際の画像形式・寸法を検証し、4096px／400万画素を上限とする。リクエスト全体64KiBの上限もWebで事前確認。大きな証拠画像を扱う専用ストレージは今回追加しない。
- **入力位置**：地図未設定時のダミー地図で座標が動く動作と、座標を住所として埋める動作を廃止。地図キーがない場合は明示し、正確な緯度・経度を入力する。Maps設定済みの場合の実地図・ピン選択は維持。Places APIは使わない。
- **状態・旧データ**：公開中の申請者も新版を編集できるよう修正。申請名がない旧データは施設名で表示し、APIでの審査を妨げない。有効期限は既存仕様どおり任意。参考URLまたは参考画像と根拠原文を申請時に求める。公式サイトは任意、入力時はHTTPS。
- **補助案内**：ブラウザのローカル保存が使えなくても、案内の保存失敗をログイン失敗として表示しない。

## 検証

- Go：`go test -race ./...`、`go vet ./...` 成功。運営による申請者操作の拒否、審査画像の公開除外、画像検証、旧申請の互換性を追加確認。
- 管理Web：静的チェック問題なし、4テスト通過。自動保存中の追加編集が別POSTを作らず、保存後の同じIDへPUTされる回帰テストを含む。
- 共通Dart契約：3テスト通過。実GoデモへのDart実接続で登録→申請→別権限による承認→公開取得→停止を確認。画像付きのJSON契約と運営の下書き変更403も確認。
- ブラウザ：架空データで入力→自動保存→再読み込み→再編集→申請→運営ログイン→承認→理由付き公開停止まで確認。住所・連絡先・根拠の保持と、停止後の公開一覧が空になることを確認。[承認時の画面](../output/postcheck-admin-integration-v16/operator-approved.jpg)。
