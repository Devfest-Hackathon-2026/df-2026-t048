# 利用者・施設・最終適用のON/OFF表示

2026-11-10の利用者指示に対応。利用者と施設の共通項目をORで適用し、アプリでそれぞれの設定と最終状態を確認できるようにした。

| 利用者 | 適用中の施設 | 最終適用 |
| --- | --- | --- |
| OFF | OFF | OFF |
| ON | OFF | ON |
| OFF | ON | ON |
| ON | ON | ON |

## 最新mainとの統合

プッシュ前のfetchで、mainに共通12項目・企業モード削除・管理Webの入力簡素化が先行していたため、その仕様を維持して統合した。作業中の7項目版や別の`enabledChecks`形式はmainへ持ち込まず、既存の`CheckTarget`／`disabledTargets`／施設の`checkTargets`を使う。

共通項目は連絡先、登録ワード、写り込んだ文字、人物、告知のタイミング、内容の確認（AI）、パソコン・スマホ、ホワイトボード、お酒（ワイングラス）、本・資料、額縁、ポスター。種類と日本語名は管理Web・公開API・利用者設定と同じものを使う。

## 表示と処理

- ホーム／撮影画面の「場所のルール」を開くと、全12項目について「利用者ON/OFF」「施設ON/OFF」「最終ON/OFF」を日英表示する。
- 投稿に適用した施設の情報ボタンも「ルールと適用状況」へ変更し、撮影時の施設・版に対する状態を表示する。
- 施設全体がOFF・未適用・期限切れなら、施設の項目を合成せず利用者設定だけを表示する。施設スイッチや対象施設の更新に追従する。
- `ReviewPreferences.effectiveEnabled()` を、候補の表示判定とUIの共通のOR判定として使う。片方のOFFで他方のONを抑制しない。
- 最新mainの追加指示に従い、既存の施設原文・登録ワードに該当する候補（`ruleEvidence`）は別途表示する扱いを維持し、その例外をUIにも明記する。
- 端末内AIの設定を別表示し、ONを実行完了・精度の保証・施設の許可と表示しない。AIの利用設定やモデル準備状態を施設から上書きしない。
- 検出を全実行した後に候補を除外する最新mainの方式を維持する。モデルの変更・最適化は行っていない。
- ライブ表示の無効化キーへルールダイジェストを加え、版番号が同じでも施設項目が変われば旧候補を破棄する。

施設の登録・委任確認・申請・承認・公開契約、個人設定の保存形式、画像・モデル・ライセンス関連の先行変更は維持する。クラウドAIへの送信や一般利用者のログイン・クラウド保存は追加しない。
