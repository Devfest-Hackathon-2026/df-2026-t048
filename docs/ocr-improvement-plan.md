# 文字の見落としを減らすための検証

更新：2026-11-08。写真・カメラの文字認識を端末内で改善するための仮説。実測や改善の達成を意味しない。

## 現状

撮影中はiPhoneのフレームをML Kit日本語文字認識に渡し、撮影後は長辺最大2400pxの画像を再認識する。どちらも認識に失敗した文字の領域は候補にならない。ぼけ、距離、文字サイズ、光、角度、手振れなどのどれが支配的か未測定。近づく・ピントを合わせることで入力を良くする案と、画像処理やモデルを変える案を比較する。

Googleは入力画像の文字サイズと焦点が認識精度に重要と説明し、目安として1文字16×16px以上を挙げる。[ML Kit iOS](https://developers.google.com/ml-kit/vision/text-recognition/v2/ios)

## 次の実験

1. 架空の電話番号・メール・住所などを印刷／表示し、距離、焦点、照明、傾き、文字サイズを変えた画像セットを作る。撮影中と撮影後は別々に評価する。
2. 正解領域を人が記録し、見逃し率・誤検出数・位置ずれ・応答時間を計測。個人情報らしい文字を見逃した割合を重要指標とし、枚数と条件を明記する。
3. 現状ML Kitを基準に、撮影時の「近づく・ピント」案、画像の拡大やコントラスト等の前処理、必要なら端末内の別モデルを同じ素材で比較する。過剰補正による誤検出や時間増加も測る。
4. 画像理解モデルは、読めない箇所の推測・幻覚を事実と扱わず、文脈上の確認候補として比較する。モデルを導入する場合も、画像・OCRのクラウド送信はしない。
5. 認識できない場合の手動範囲指定・最終確認を維持。撮影品質による情報欠落はAIでも必ず復元できない。

## ぼかしの仕様

個人モードの画像編集に「ぼかし／黒塗り」を追加。選択範囲内を強くぼかし、その外側だけを滑らかにつなぐ。表示オーバーレイではなくPNGの画素を変更し、修正後に再チェックする。ぼかしは匿名化・機密保持を保証せず、重要情報には黒塗りを選べる。企業モードは黒塗りを維持。撮影中の映像をぼかして保存する機能ではない。実機の品質・速度とOCR改善効果は未測定。
