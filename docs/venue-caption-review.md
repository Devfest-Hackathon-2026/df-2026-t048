# 施設ルール原文と投稿文の意味照合

2026-11-10、利用者が承認した「施設が決めた非公開情報を投稿文で漏らす前に気づかせる」方針をモバイルアプリへ実装。

## 使う場面

下表は架空の条件・投稿文。施設ルールが該当する制限を含む場合に確認を促す。実施設の規則や、実モデルが検出できた結果を示すものではない。

| 場面 | 施設ルールの例 | 投稿文の例 | 確認したい内容 |
| --- | --- | --- | --- |
| 研究室・企業見学 | 未発表製品の仕様・性能は非公開。公開済みの情報は対象外 | 充電なしで一週間動くらしい | 製品名を出さず性能を説明していないか。公開済み・掲載許可済みか |
| 先行上映 | 解禁前は結末を非公開 | 最後に主人公が戻ってきて感動した | 結末の公開条件・解禁時刻 |
| イベント | 出演者の控室・移動予定は非公開 | あの人、今は西館3階で待機してるらしい | 控室の言い換えや現在地につながる説明 |
| 工場見学 | 生産能力・増産計画は非公開 | 一時間に500個作れるらしい。倍にする計画もあるって | 生産量・今後の計画の言及 |

## 動作

1. 適用中の施設と版を `CheckDraft` → `ContextAnalysisPort` → `ConfiguredGemmaAdapter` → `LocalGemmaAdapter` に渡す。基本の顔・OCR・連絡先・登録ワード・告知語チェックは維持する。
2. 投稿文があり、有効な施設原文がある場合だけ、原文全体・対象エリア・確認時刻・解禁時刻をJSONデータとして既存の端末内Gemma入力へ追加する。クラウド推論や追加の通信はない。
3. 単語一致以外の言い換えや文の組合せ、原文の条件・例外も考慮するよう指示する。ルールにない禁止事項を作らず、許可・機密性・公開済みかを推測しない。写真の自由な物体特定は今回の範囲外。
4. 施設ルール由来の候補は `captionQuote` と `ruleQuote` を必須とする。投稿文の引用が送信した範囲内にあり、元の全文で一意に特定でき、ルールの引用が実際に渡した原文の連続した部分文字列であることを検証する。架空の引用・未知フィールド・写真へのルール参照は破棄する。
5. 投稿文の該当箇所を見出し、AIの確認質問と「関連する施設ルール（原文）」、施設名・版・引用をレビューに表示する。ルールの引用は省略表示せず、原文画面へのボタンを維持する。「残す／隠す」で判断し、公開は利用者が決める。
6. 施設OFF・失効時は原文をAIへ渡さず、原文に基づく候補を作らない。施設の停止・更新中に遅れて返った結果を適用しない。版番号が同じでも原文等のダイジェストが変われば旧結果を無効にする。解禁境界は登録ワードが空でも結果の再確認対象にする。

AI候補は一般の文脈候補と合計最大5件。基本チェックにはこの上限を適用しない。引用の検証は、モデルの説明が意味的に正しいことを保証しない。

## 上限と未実施の表示

- 施設原文＋対象エリアが合計1,600 UTF-16コード単位以内の場合だけ意味照合に使う。上限超過では原文を途中で切らず全体を除外し、「施設ルールが長いため意味の照合は未実施」と案内する。条件の例外だけが欠落する切り方を避ける。
- 原文が空の場合は原文なしとして案内する。構造化された可否表示・登録ワード照合は継続する。
- 施設原文を渡す場合は投稿文の先頭2,000、OCRの合計800コード単位を上限とする。上限で落ちた投稿文・OCRがあれば一部対象外と表示する。基本チェックは元の全文で実行する。
- 一般のAI確認は既存の投稿文3,000・OCR1,600の上限を維持する。引用は600コード単位まで。
- AIオフ・未準備・実行失敗・タイムアウト・利用者による追加確認終了では意味照合の未完了を表示する。候補0件を公開可能の判定にはしない。
- `ContextResult.venueReviewCompleted` は原文付きでモデルが実行されJSONを解析できたという実行状態であり、漏れなく確認できたことや掲載許可を意味しない。

## 検証範囲

自動テストは架空の施設・投稿文・固定のモデル応答を使う。`test/venue_caption_review_test.dart` の26件で、登録ワードを含まない4場面の応答受け渡し、引用検証、意味照合未完了の表示、基本チェック継続、停止・更新時の無効化、日英の小画面・文字拡大表示、文章の残す／隠すを確認した。

2026-11-10に `flutter test --no-pub` を実行し、今回追加の26件を含む全261件が成功。`flutter analyze --no-pub` は問題なし、`git diff --check` も通過。静的解析で指摘されたテスト内の不要な文字列補間の括弧を修正した後、追加26件も再実行して成功。

**今回、iPhone／Android実機での新しいプロンプトの推論・検出精度・誤検出・処理時間・メモリ負荷は未検証。実装完了時点では配布更新は未実施。その後の利用者の配信指示でビルド11をTestFlightへアップロードし、Appleの処理完了・説明文Saved・既存内部グループ2名への追加とTesting表示を確認（[最新配布状態](testflight.md)）。Google Playの配布更新は行っていない。** 固定応答のテストを、実際のGemmaが上表を検出できる実証とは扱わない。

実機では上表の各投稿に加え、制限のない感想、公開済みの例外、解禁前後、無関係な施設ルールを対照として確認する。写真併用時・長文時の上限と処理失敗も扱い、原文・投稿文・AI出力をログに残さず、候補件数・成功／失敗・処理時間だけを記録する。
