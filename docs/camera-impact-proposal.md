# PostCheck：価値が見える撮影体験の提案

2026-11-08。ユーザーとの相談用の提案であり、以下の追加UIは未実装・未承認。内カメラの向きの不具合修正とは分ける。

## 中心にする体験

「伝えたいものを残して、写すつもりのなかった情報だけを隠す」。現状のカメラと注意文だけでは、利用者の判断や写真の改善が見えにくい。発見→選択→変化を同じ写真の上で見せる。

1. 撮影中は候補の位置と短いラベルを対応させる。登録ワードや連絡先など根拠のある対象だけ示す。注意文と枠が離れて理解しづらい状態を改善する。常時点滅・大きな警報や、実処理と無関係なスキャン演出は避ける。
2. 撮影後、候補をタップすると該当部分を拡大し、「隠す／残す」をその場で選べる。利用者が選んだ範囲だけを処理し、対象を残した写真の変化を見せる。本人・他人、掲載同意、機密性を顔だけから決めない。
3. 仕上がりに加工前後の比較スライダーを設ける。変更した箇所と残した構図がすぐ分かる。元画像は確認中のメモリに限り保持し、保存・共有は再チェック済みの加工画像のみ。比較中に元画像を誤って書き出さない。

最初に作るなら3と2。既存の静止画編集・再チェックの流れを活用でき、デモで価値を見せやすい。撮影中の追従マスクは、移動時の遅延と枠のずれへの対策が必要なため、この提案の必須範囲にしない。

## 30秒のデモ案

架空イベントの写真に、残したい登壇者・イベント名と、隠したい架空の連絡先・登録した未公開企画名を用意する。カメラで位置に気づき、撮影後に隠す対象を選び、加工前後を指で比較する。最後に同じ写真を再チェックして書き出す。実際に検出できた対象だけ実演し、見落とし・処理時間も事前に測る。

主役は「何件危険だったか」というスコアではなく、公開したい写真を必要な変更だけで仕上げた結果。端末内解析は、写真・OCRをクラウドAIへ送らない構成として説明し、SDK診断通信も含む「外部通信ゼロ」とは表現しない。

## 確かめること

- 初見の人が枠とラベルから、どこを確認するか分かるか。
- 隠す必要のある対象を選べたか、残す対象まで消していないか。
- 加工前後でどこが変わったかを説明できるか。
- 既存UIと比べた所要時間・操作回数・見落とし。改善を測るまでは効果を断定しない。
