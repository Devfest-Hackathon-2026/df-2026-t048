# SNS別共有（V14）

更新日：2026-11-08。ユーザー指定により、投稿前に確認・修正した内容をSNSへ渡す導線を追加。公開の最終操作は利用者が共有先で行う。

## 動作

| 共有先 | 文章のみ | 写真あり |
| --- | --- | --- |
| X | `https://x.com/intent/tweet?text=...` を開く | 加工済みPNG＋文章をOS共有へ。利用者がXを選択。文章をコピー |
| LINE（友だち・グループ） | `https://line.me/R/share?text=...` で送信先を選ぶ | 加工済みPNG＋文章をOS共有へ。利用者がLINEを選択。文章をコピー |
| Instagram通常投稿 | 写真がない場合は選択不可 | 加工済みPNG＋文章をOS共有へ。文章もコピーして貼り付けを補助 |
| Instagramストーリーズ | 文章から画像を作る | 写真＋文章・写真に重ねる・写真のみを選択して9:16画像を作成 |
| Threads | `https://www.threads.com/intent/post?text=...` を開く | 加工済みPNG＋文章をOS共有へ。利用者がThreadsを選択。文章をコピー |
| 公式LINE宛て | IDを指定し `oaMessage` で文章入りのトークを開く | 同じく文章のみ。写真は別途保存・追加することを画面で説明 |
| その他 | 既存のOS共有 | 既存のOS共有 |

写真の共有では、特定SNSの拡張を強制選択する非公開APIは使わない。選択したSNS名は導線の案内であり、OS共有シートでは利用者が共有先を選ぶ。受信側が文章を取り込むか、通常投稿／ストーリーズのどちらを提示するかはSNSアプリのバージョン・状態に依存する。未インストールのSNSは共有候補に出ない場合がある。文章入りURLが開けない場合や長すぎる場合はOS共有へ戻す。

公式LINE宛て機能は「利用者から公式アカウントへ送る」機能。公式アカウントとしての配信、グループの自動指定、Messaging APIによる自動送信は行わない。アカウントIDはその操作時のみ利用し、クラウド・設定へ保存しない。

## ストーリーズ画像

- 端末内で1080×1920のPNGを作成。写真は縦横比を保ち、切り抜かず全体を配置。OS側の上部・下部UI用に余白を確保する。
- 文章は画像の一部として描画するため、Instagram内で編集できる文字にはならない。アプリ内で確認済みの文章を使用し、共有直前に未確認の文章を追加する編集欄は設けない。
- 表示と共有で同じレンダラーを使う。文章は収まる範囲で縮小し、最小サイズでも収まらない場合は明示して共有ボタンを無効化する。黙って切り詰めない。
- MetaアプリID未取得というユーザー回答に合わせ、現在は9:16画像をOS共有へ渡す。共有先でストーリーズを選ぶ。文章もクリップボードへコピーする。
- 任意設定 `INSTAGRAM_APP_ID` をビルド時に追加すれば、iOSの `instagram-stories://share?source_application=...` とローカルの期限付きペーストボードを使う直接連携を試せる。IDなし・Instagramなし・起動失敗時はOS共有へ戻す。実際のMetaアプリIDを使った直接連携は未検証。現在は追加キー不要。
- 設定例は `postcheck/config/rules.example.json`。実設定はGit対象外のローカル設定に記載する。バックエンドやSNSのOAuthログインは今回不要。

## 分離とデータ

`domain/social_share.dart` に共有先・結果・ポートを定義。コントローラは確認済み内容だけを渡し、SNSのURL起動・コピー・共有・画像合成はadaptersで処理。UIは選択とプレビューを担当。

共有できる条件は従来と同じ。未確認候補、未適用の修正、施設ルール変更、再チェック待ちがある場合はSNS共有も不可。画像を画素へ反映したPNGとして生成し、EXIF・GPS・埋め込みサムネイルを引き継がない。写真・投稿文を独自サーバーへアップロードせず、選択操作後に共有先へ渡す。クリップボードへの文章コピーはSNS共有を選んだとき、もしくは「投稿文をコピー」を押したときのみ。

URL起動・共有シートの終了は投稿成功を意味しない。「投稿済み」「送信済み」と表示しない。SNSから戻った後も下書きと加工結果を保持する。
