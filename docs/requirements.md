## 1. 目的と解決する課題

SNSに写真や文章を投稿する際、名札の連絡先、背景の資料、写っている人、告知前の企画への言及を見落とすことがあります。PostCheckは、撮影中と公開前の2段階で確認のきっかけを作り、意図しない公開によるトラブルを減らすことを目指します。

プロダクトの中心は、**「ここ、公開して大丈夫？」と気づかせ、投稿者が判断できること**です。炎上の発生確率を予言したり、公開の適法性・安全性を保証したりする機能にはしません。

### 1.1 最初に想定する利用者

- 最初の検証対象：サークル・学生団体などでイベント写真と投稿文を作るSNS担当者。
- 将来の対象候補：制作物や仕事の様子を投稿するクリエイター・広報担当者、写り込みを確認したい個人。

優先する対象者は仮説です。最初のデモは「イベント写真と告知文」に絞ります。対象者へのヒアリングと効果検証は未実施として扱います。

### 1.2 利用者に提供する価値

1. 撮影中に写り込みに気づき、構図を変えて撮れる。
2. 撮影後・写真選択後に、写真と文章をまとめて確認できる。
3. 指摘の理由と対象箇所が分かり、必要な部分だけ修正できる。
4. 解析する写真・文章をクラウドAIへ渡さずに利用できる。
5. AIが使えない場合も、基本チェックから保存・共有まで進める。

## 2. 基本方針とMVPの範囲

### 2.1 必須方針

- 解析対象の写真・カメラ映像・文章・OCR・個別登録ワードは端末内で処理する。
- 撮影中はML Kitによる軽い検出、撮影後は静止画の詳しいチェックとGemmaの文脈確認に分ける。
- 検出は確認候補であり、人物の特定・掲載同意・機密性の断定をしない。
- 自動で黒塗りを確定せず、利用者が隠す／そのまま使うを選ぶ。
- 自動投稿しない。書き出す内容と共有先を利用者が選ぶ。
- 初回起動時のアカウント作成・SNSログインを基本利用の必須条件にしない。Gemma 4 E2Bは初回起動後にWi-Fiで自動取得し、手動のモデル追加を不要にする（2026-11-09最新ユーザー承認）。AI補助は初期ON、既存のOFF設定と取得停止を保持する。準備中も基本チェックを利用できる。
- 中核ロジックを入力画面やSNSのインターフェースから分離する。
- 施設を毎回選ばせず、端末GPSと自前の登録施設座標から近接候補を決める。Google Mapsは地図表示を担当し、Places APIは使用しない。
- 施設ルールは基本チェックに追加する。施設なし・未取得・オフでも顔・連絡先・個人の登録ワード等のチェックを継続する。
- 一般利用はアカウント不要を基本方針とし、ログイン情報を収集しない。公開ルールだけを取得する。Google／Appleログインと個人設定のクラウド保存・復元は追加予定に含めず、組織限定配信は後続フェーズとする。詳細は第7.3節を参照。

## 3. 全体の利用フロー

| 場面 | 利用者の操作 | アプリの動作 | 次の状態 |
| --- | --- | --- | --- |
| 起動 | カメラ／写真／文章を選ぶ | 位置利用を説明し、許可済みなら前景で測位。基本チェックを先に利用可能にする | 入力中または撮影中 |
| 施設に近づく | 原則操作不要 | 登録施設と距離照合し公開ルールを取得。「近くの施設：〇〇／施設ルールON」と表示 | 基本＋施設ルール |
| 施設が違う／入っていない | OFFまたは施設を変更 | 施設ルールだけ外す。基本チェックと入力を保持 | 基本チェック継続 |
| 施設にいる | ONのまま使う／オフからONへ戻す | 有効な公開ルールを適用。必要時に原文を確認できる | 基本＋施設ルール |
| 撮影中 | カメラをかざす | 直近の検出対象へ枠と注意を重ねる | 撮影を続けられる |
| 構図調整 | 名札・資料を画角から外す | 新しい映像に合わせて注意を更新 | 再度撮影できる |
| 撮影 | シャッターを押す | 静止画を取得し、採用／撮り直しを提示 | 撮影後の確認 |
| 入力 | 写真を採用し文章を整える | 写真と文章を保持 | チェック可能 |
| チェック | 投稿前にチェックを押す | 基本チェック、可能ならAI補助 | 候補一覧または一部未完了 |
| 判断 | 候補ごとに隠す／使うを選ぶ | 対象と理由、加工後の状態を表示 | 修正・確認中 |
| 修正 | 黒塗りや文章編集を行う | 変更後の結果を未チェックとして扱う | 再チェック待ち |
| 再チェック | 修正後を確認する | 実際の加工済み写真・文章を解析 | 最終確認可能 |
| 書き出し | 内容を見て保存・共有する | 表示した加工済みデータをOSへ渡す | OSの保存・共有先選択 |

写真だけ・文章だけの利用を認めます。カメラを使わない場合は撮影中の工程を通りません。設定は必要なときだけ開きます。モデル追加の操作は不要です。

## 4. 機能要件

### 4.1 入力・下書き

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-IN-01 | P0 | カメラアイコン＋「カメラで撮る」、写真アイコン＋「写真から選ぶ」を表示する | アイコンだけに依存せず、両方の入口を起動直後に見つけられる |
| FR-IN-02 | P0 | 写真1枚と任意の文章を入力・変更・削除できる | 写真のみ／文章のみ／両方でチェック可能。両方空のときは無効 |
| FR-IN-03 | P0 | キャンセル・設定への移動で入力を保持する | 写真選び直し・撮り直しの取消で既存写真と文章が失われない |
| FR-IN-04 | P0 | 架空の写真・文章で試せる | 利用者の実データやSNSログインなしで一連のデモを試せる |

入力形式はJPEG・PNGを基本とし、iPhoneカメラ／OS写真選択から受け取る形式の正規化を実機で検証します。HEIC・Live Photos等の全面対応は未確定です。非対応時は理由と写真の選び直しを表示します。

### 4.2 撮影中の写り込み警告

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-LIVE-01 | P0 | 専用カメラ画面でプレビューを表示し、静止画を撮影できる | 閉じる・撮影・前後カメラ切替・写真選択ができ、連打で二重処理しない |
| FR-LIVE-02 | P0 | 映像の一部フレームを端末内で解析する | 写真・動画として保存・アップロードせず、基本検出を更新できる |
| FR-LIVE-03 | P0 | 文字・連絡先形式・登録ワード・顔の位置を検出し、枠と短い注意を表示する | メールなら「連絡先が写っています」、一般文字なら「この文字、公開して大丈夫？」など根拠に合う表示 |
| FR-LIVE-04 | P0 | 同じ対象への注意をまとめ、撮影を妨げない | モーダル・音・振動を毎フレーム出さない。シャッターは注意表示中も使用可能 |
| FR-LIVE-05 | P0 | 古い映像の枠や別カメラの結果を表示し続けない | フレーム時刻とセッションを管理し、回転・切替・画面離脱で結果を破棄する |
| FR-LIVE-06 | P0 | 解析中・一時停止・検出失敗を候補なしと区別する | 未処理の状態を「問題なし」「検出なし」と表示しない。失敗しても撮影後チェックへ進める |
| FR-LIVE-07 | P0 | 撮影後の写真を改めてチェックする | ライブの枠や「検出なし」を、静止画の確定結果や公開許可として引き継がない |

**表示ルール**

- ライブ画面では「文字」「連絡先」「登録ワード」「人物」のように短く伝える。名前・機密資料と断定しない。
- 顔の枠は人物の位置だけを表す。誰なのか、掲載許可があるかは推測しない。
- 目立つ注意文は最大1つ、その他は件数などでまとめる。枠の数と選び方は実機評価で調整する。
- 連続検出・消失猶予などでちらつきを抑えつつ、画角から消えた対象の枠を残さない。
- プレビューの拡大・クロップ・回転・前面カメラの鏡像を考慮し、枠が対象と対応すること。
- 小さい文字、暗所、手ぶれ等で読めない場合に、読めたような表示をしない。
- Gemmaを毎フレーム実行すること、撮影中の炎上確率判定、注意対象の自動黒塗りはP0に含めない。

GoogleはML Kitの画像・動画の文字認識と顔検出を案内しています。日本語などの認識はラテン文字より遅いため、本アプリでの更新間隔は実機測定で決めます。[文字認識の公式資料](https://developers.google.com/ml-kit/vision/text-recognition/v2/ios)、[顔検出の公式資料](https://developers.google.com/ml-kit/vision/face-detection/ios)

### 4.3 撮影後・写真選択後のチェック

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-CHECK-01 | P0 | 日本語OCR、顔の位置、連絡先、登録ワード、告知関連語を確認する | 対象箇所と短い問いかけを持つ候補を生成する |
| FR-CHECK-02 | P0 | 利用可能な端末内モデルで写真・文章の文脈確認を補助する | モデル準備済みかつAIオンのときに実行。準備なし／オフ／失敗を区別する |
| FR-CHECK-03 | P0 | 各チェックの実行状態を表示する | OCR失敗を含む一部未完了、AIだけ未実行、候補なしを混同しない |
| FR-CHECK-04 | P0 | 入力・設定変更や中止で古い結果を無効にする | 前の写真・文章・ワード設定での非同期結果が新しい画面に混ざらない |
| FR-CHECK-05 | P0 | AIの指摘を検証可能な対象に限定する | 実在するOCR ID・原文引用・写真全体のみ。未知IDや生成座標を採用しない |
| FR-CHECK-06 | P0 | 適用中の施設ルール原文と投稿文の意味を端末内AIで照合する | 単語一致に限らず公開制限への言及を確認候補として提案。投稿文とルールの実在する引用・施設名・版をセットで表示。AIオフ・未準備・失敗・原文なし・長さ上限超過は照合未完了／未実施を明示し、基本チェックを継続する |

AIには「公開してよいか本人に確認したい箇所」を短い質問で提案させます。入力文・OCR・写真中の命令は検査データとして扱い、アプリの指示として実行しません。AIの候補数は1回最大5件を現行契約として引き継ぎます。基本チェックの件数にはこの上限を適用しません。

モデルの入力上限で写真・文章・OCRの一部を対象外にした場合は、全体を確認済みと誤認させないこと。長文や大量のOCRへの対応方針は、第12章の入力上限と合わせて確定します。

2026-11-10のユーザー承認で、研究・製品の詳細、作品の結末、出演者の控室・移動予定、生産量など、**施設が原文で制限した情報を投稿文で漏らす場面**を対象に追加。AIは掲載許可や公開済みかを推測せず、最終判断は利用者へ委ねる。原文＋対象エリアが1,600 UTF-16コード単位を超える場合は、例外条件を途中で切らず施設原文の意味照合全体を省略する。照合時は投稿文の先頭2,000・OCR合計800コード単位を上限とし、省略を表示する。基本チェックは全文を対象とする。実装・検証の範囲は[施設ルールと投稿文の意味照合](venue-caption-review.md)を参照。

### 4.4 候補の一覧と利用者の判断

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-REVIEW-01 | P0 | 同じ対象・同じ理由の候補をまとめる | 同じ名札にルールとAIが反応しても、同じ判断を重複して要求しない |
| FR-REVIEW-02 | P0 | 候補と写真上の位置・文章の該当箇所を対応させる | 候補を選ぶと対象が分かる。位置が不明なら写真全体の確認と明記する |
| FR-REVIEW-03 | P0 | 「このまま使う」「隠す／修正する」を利用者が選ぶ | 未確認・そのまま使う・修正済みを区別し、選択を戻せる |
| FR-REVIEW-04 | P0 | 未確認を残したまま書き出さない | 候補ごとの判断で進め、同じ確認の追加チェックボックスや連続モーダルは設けない |

先に連絡先・登録ワードなど根拠が具体的な候補を提示し、一般的な文字の写り込みと区別します。表示順を危険度スコアと説明しません。候補が多い場合も一覧は省略せず確認可能にします。

再チェックで判断を維持する場合は、対象・内容・根拠が同一と確認できるものに限ります。対応付けできない候補は未確認へ戻します。変更後の写真・文章に、変更前の「確認済み」をそのまま流用しません。

### 4.5 修正・再チェック

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-EDIT-01 | P0 | 画像の対象領域を不透明な黒塗りで隠す | 書き出す画像の画素が変わり、表示用の枠や透過レイヤーを外しても文字が現れない |
| FR-EDIT-02 | P0 | 手動範囲指定と変更の取消ができる | 位置不明の候補でも範囲を指定でき、元に戻す・リセット・キャンセルが使える |

### 4.7 設定・モデル・権限

| ID | 優先度 | 要件 | 完了条件 |
| --- | --- | --- | --- |
| FR-SET-01 | P0 | 端末内の確認ワードを追加・変更・削除できる | 空白・重複を整理し、変更後に既存結果を無効にする |
| FR-SET-02 | P0 | Gemmaを初回起動後にWi-Fiで自動取得し、AIオン／オフ・進捗・取得停止・再開・ライセンスを扱う | モデルの手動追加なし。取得中も基本チェックを利用でき、サイズとSHA-256の検証が完了したモデルだけを利用する。取得済みの同じモデルはアプリ更新で再取得しない |
| FR-SET-03 | P0 | カメラ不許可・使用不可から復帰できる | 設定を開く／写真を選ぶ／入力へ戻るを提示する |
| FR-SET-04 | P0 | 解析とデータの扱いを利用前・設定画面で確認できる | 端末内解析、公開モデルのWi-Fi取得、SDK診断通信、共有時の受け渡しを区別する |

モデルはアプリ本体から分離し、最初の画面表示後にWi-Fiで自動取得します。取得中も基本チェック・修正・書き出しを継続し、初回のAI準備を起動の待機条件にしません。iOSはバックグラウンドURLSessionを使い、利用者の取得停止を保存します。サイズ2,588,147,712 bytesと固定SHA-256を少量ずつ読んで検証し、完了前・破損ファイルはAIへ渡しません。検証済みモデルは同一モデルのアプリ更新で再取得せず、OSバックアップから除外します。OS・通信・空き容量によって待機し、再開時に最初から取得する場合があります。写真・文章・OCRは送信しません。[実装・検証範囲](fast-install-model.md)を参照。

### 4.8 現在地・近くの施設ルール（今回の必須仕様）

| ID | 優先度 | 要件 | 完了条件 |

**適用状態と操作**

| 状態 | 表示例・動作 |
| --- | --- |
| 基本のみ | 「基本チェック中」。施設なしでも通常の撮影・確認へ進める |
| 自動取得中 | 「近くの施設：〇〇／ルール取得中」。基本チェックは継続 |
| 自動適用 | 「近くの施設：〇〇（推定）／施設ルール ON」。OFF・施設変更・原文を開く操作を提供 |
| 利用者がOFF | 「〇〇の施設ルール OFF／基本チェック中」。再ONは明示操作。自動測位で戻さない |
| 手動選択 | 選択施設とON/OFFを維持。「自動に戻す」で測位候補へ戻れる |
| 取得失敗・位置不明 | 状態と再試行・一覧・QRを示す。新規の自動適用はせず基本チェックを継続 |

自動選択は同時に1施設。複数の近接候補がある場合も最寄りを初期候補とするが、「候補を変更」で一覧・地図から切り替えられる。測位が古い・精度が不十分なら候補だけを表示して自動適用は保留する。しきい値は第12章の仮置きとして実機調整する。

撮影前の自動モードでは施設の圏外に安定して出たら施設ルールを外す。手動選択は維持し、現在地と異なる可能性を示す。位置取得中断・復帰時は再測位・再取得し、過去の位置を最新と見せない。OFF指定は撮影・画面遷移・一時バックグラウンドでもセッション中維持し、プロセス終了後はリセットする。利用者は「自動に戻す」でその抑制も解除できる。

適用中のルールが撮影不可なら、カメラへ入る前に案内する。既にプレビュー中に取得した場合は「この場所では撮影不可の案内があります」と表示して当該ルールON中の撮影を停止し、原文・施設変更・OFFへ進める。OFFは「施設にいない等のため適用を外す」操作であり、撮影許可の取得を意味しない。施設が撮影可でも基本の写り込み確認は省略しない。

MVPは自前の少数施設一覧・公開ルールを匿名APIで取得して端末内で距離照合する。既存の `GET /v1/venues` の一括取得でもよく、施設ごとの別APIは必須にしない。施設一覧の取得失敗時に架空データへ自動置換しない。デモは明示したローカルデータで行う。

永続オフラインキャッシュは今回必須にしない。同一セッションに保持した版は取得時刻と「最新未確認」を表示し、自動で別施設に適用しない。位置変化・再取得・有効期限・解禁時刻で結果が変わる場合は確認済み状態を再評価する。解禁は撮影日時ではなく公開を確認する時点の日時で判断する。

### 4.9 施設ルールの登録・公開と後続フェーズ

- 登録・編集は利用者アプリから分離したWeb管理画面で行う。施設名・座標・対象範囲、撮影／SNS公開／商用利用条件、ワード、解禁・期限、原文・URLを登録し、申請・承認後に配信する。
- 承認までは旧公開版を維持。公開停止、差し戻し理由、更新競合、審査の対象版固定を維持する。一般公開するワードと原文をプレビューで明示する。
- 一般利用者のGoogle／Appleログインと個人設定のクラウド保存・復元は追加予定から外す。既存の未接続コードは履歴として保持し、有効化や削除は今回行わない。一般利用者の導線で提供予定とは案内しない。組織限定ルール配信は後続フェーズとして維持し、必要な認証の変更は別途判断する。
- 今回の管理操作は既存のローカルデモと架空データで検証。本番の施設登録・承認・公開停止には管理者の認証・認可が必要であり、一般利用者のアカウント不要方針を理由に匿名書き込みAPIを公開しない。管理画面の本番公開も認証設定後とする。
- クラウド配置・課金設定は延期を維持。将来配信を公開する際も、匿名の閲覧と管理者の更新権限を分離する。

## 6. 状態管理と例外時の振る舞い

| 状態・出来事 | 必須の振る舞い |
| --- | --- |
| 写真・文章がともに空 | チェック無効。何を追加すればよいか表示 |
| カメラ起動中 | 権限を必要な場面で要求。起動失敗時は写真選択・入力へ戻れる |
| ライブ解析中・一時停止 | 候補なしと区別。撮影機能と不要に連動してロックしない |
| アプリがバックグラウンドへ移動 | カメラとフレーム解析を停止。復帰後は新しいセッションで開始 |
| 画面回転・前後カメラ切替 | 古い枠・処理結果を破棄して座標系を更新 |
| 写真を採用 | 入力に反映。勝手に解析・共有を開始しない |
| 静止画チェックを中止 | 入力を保持して戻る。中止後の結果を反映しない |
| OCR・顔検出の一部失敗 | 該当ステージを未完了として示し、成功した結果は残す |
| AI未準備・オフ・失敗 | 基本チェックから進める。クラウドAIへ代替送信しない |
| 入力・ワード設定の変更 | 古いレポートと不整合な確認済み状態を破棄 |
| 加工中 | 二重操作を抑え、完成していないプレビューを共有しない |
| 共有先をキャンセル | 最終プレビューへ戻り、下書きと加工結果を保持 |
| 容量不足・画像非対応・モデル不正 | 内容を漏らす生エラーを出さず、選び直し・削除・再試行等を案内 |
| アプリ終了・再起動 | 下書き・結果の永続復元はしない。設定と取得済みモデルは保持 |

基本チェック自体が一部未完了の場合も、何を確認できなかったかを明示した上で手動確認・修正・共有へ進めるものとします。「すべてチェック完了」という表示はしません。最終画面の表示状態と、実際に実行したステージを一致させます。

| 施設ルールのON/OFF・手動指定 | セッション内。OFF指定は同施設へ再進入しても維持 | 送信・個人履歴化しない |
| 管理者の申請データ | 今回はローカルデモの架空データ。本番保存は後続接続時に認可・暗号化 | 一般公開に承認した本文以外の連絡先・組織限定情報は公開APIへ出さない |

### 7.1 通信の境界

- ライブ検出・静止画チェックに、投稿内容をクラウドAIへ送る経路を作らない。
- 一般ルール・モデル情報を取得する場合も、入力写真・文章・OCR・登録ワードを要求に含めない。
- アプリ独自の診断ログへ、生の投稿内容・AI出力・入力を含み得る例外を出さない。
- アプリの取得・更新やクラウド実行基盤への接続では、IPアドレス等の通常の通信メタデータが発生し得る。
- 写真ライブラリや共有先の既存の同期設定は、本アプリが一括管理するものではない。

ML Kitの公式説明では入力と結果の処理は端末内で行われますが、SDKの利用・性能等のメトリクス通信があります。本アプリの説明は「写真・文章の解析は端末内」とし、「Googleへの通信が一切ない」とはしません。[ML Kitの公式プライバシー説明](https://developers.google.com/ml-kit/terms)

### 7.2 保持・削除・バックアップ

- 下書き・解析結果の自動クラウド保存や投稿履歴の永続化はP0に含めない。
- 元のライブラリ写真、利用者の任意ファイル、共有先の保存物を自動削除しない。
- 一時データの清掃はアプリが作った専用領域だけを対象とする。
- モデル・設定等のアプリ専用領域は、現行方針に従いOSバックアップから除外し、対象OSで確認する。
- カメラと、利用中の近接施設判定のための位置情報を必要な場面で要求する。位置拒否でも基本チェックを使える。常時位置情報・バックグラウンド追跡・マイク・連絡先アクセスは要求しない。

### 7.3 一般利用者のアカウントとログイン情報

2026-11-10のユーザー承認により、一般利用者のアカウント不要を基本方針とする。単なるログイン実装の延期ではなく、必要性が生じて改めて判断するまで追加予定に含めない。

- 一般利用者にアカウント作成・Google／Apple／SNSログインを求めず、ログイン用のUID・メール・表示名・認証トークン等を収集・保存しない。匿名認証で利用者アカウントを自動作成する方式も追加しない。
- 写真・文章のチェック、修正・共有、公開施設ルールの取得、端末内設定をアカウントなしで利用できる状態を維持する。
- 設定・登録ワード・個人学習の集計は端末内に保存する。個人設定のクラウド保存・復元と端末間同期は提供しない。機種変更・アプリ削除時の引き継ぎは保証せず、利用者向けの説明でこの制約を明示する。ファイルへの書き出し・読み込みも現時点の提供機能・実装予定には含めない。
- 将来、同期・復元などでアカウントが必要になった場合は、利用者の便益・収集する情報・保存と削除の方法を整理して改めて判断する。既存の認証・復元コードがあることを追加の承認と解釈しない。
- 施設管理Webは別扱いとし、施設の登録・編集・申請・審査に必要な認証・認可を維持する。管理者のUID・メール・表示名などはFirebase Auth等に残るため、サービス全体を「個人情報を一切収集しない」と説明しない。[施設管理権限](facility-access-v17.md)を参照。
- 地図・公開API・モデル取得・SDKに伴う通信や通常の通信メタデータは、第7.1節の方針を維持する。「アカウント不要」を「外部通信ゼロ」と説明しない。

今回の変更は仕様・関連資料への方針反映のみ。認証SDK・未接続コードの削除、実装変更、クラウドの設定変更・データ削除、配布更新は行わない。

## 8. 検出結果と中核データの契約

| データ | 必要な情報 |
| --- | --- |
| 入力 | 写真・寸法・向き、文章、入力リビジョン、適用ルールのバージョン |
| ライブ解析 | セッションID、フレームID・取得時刻、元画像とプレビューの対応情報、ステージ状態 |
| 観測結果 | OCRの実在ID・文字・位置、顔の位置、認識できなかったステージ |
| 確認候補 | ID、種別、短い問いかけ、写真領域／文章範囲／写真全体、ルール・ML Kit・Gemma等の根拠 |
| 利用者の判断 | 未確認／そのまま使う／隠す、判断対象のリビジョン、手動領域 |
| チェック結果 | 対象リビジョン、実行ステージと成功・失敗・未実行、確認候補、完了時刻 |
| 書き出し対象 | 最終写真・最終文章、対応するチェック結果のリビジョン |

現行の `DraftInput` / `Observations` / `Finding` / `CheckReport` / `ExportArtifact` を基礎にします。ライブ用ID・ステージ状態・ルールのバージョンなど不足項目は追加設計の対象です。座標はSDKや表示サイズから独立して扱い、回転・鏡像・クロップの変換はアダプターと表示側の境界で管理します。

## 9. 非機能要件

### 9.1 応答・資源管理

| ID | 要件 | 検証方法 |
| --- | --- | --- |
| NFR-PERF-01 | ライブ解析は処理待ちフレームを際限なく蓄積しない | 処理中のフレームを1つに制限し、不要なフレームを間引くことを確認 |
| NFR-PERF-02 | シャッター・閉じる・切替の操作を解析処理で止めない | 実機で解析中に操作し、固まりや二重撮影を確認 |
| NFR-PERF-03 | 検出器をフレームごとに作り直さず、不要時に解放する | 起動・切替・離脱・復帰の繰り返しで資源の増え続けがない |
| NFR-PERF-04 | 継続使用時の発熱・メモリ・電力負荷を測る | 実機で5分間撮影プレビューを動かし、異常終了・操作不能を確認 |
| NFR-PERF-05 | 古い検出枠を現在の確かな結果として表示しない | フレーム時刻・セッション・向きの変更を使い、遅れて完了した処理を棄却 |

性能の測定条件は「対象端末・OS・モデル・解析解像度・明るさ・文字の大きさ・前後カメラ・温度」を記録します。顔と日本語OCRを別に計測し、モデル未準備／ありも分けます。

### 9.2 品質・信頼性

- 正検出だけでなく、誤検出・見落とし・枠のずれ・重複警告を記録する。
- 一部失敗で処理全体を不要に失敗させず、完了した結果と未完了を分ける。
- 画像加工・モデル実行の失敗で元の入力を失わない。
- 候補の存在・不在を公開の許可や禁止と解釈しない。
- 生データをクラッシュ・診断ログへ含めない設計を確認する。

### 9.3 保守性・拡張性

- Flutter / Dartを基本とし、Google技術を中核に採用する。
- `domain` / `application` はUI・SDKに依存させず、写真入力・ライブ入力・AI・出力をアダプターで接続する。
- ライブの「気づき」と静止画の「レポート」を別の状態として扱う。ライブ結果で静止画レポートを上書きしない。
- 将来のSNS連携でもチェック処理を再利用できる契約を維持する。今回すべてのSNS用アダプターを作る必要はない。
- 依存関係・モデル・ライセンス・実機の対応状況を記録する。

## 12. 数値の仮置きと未確定事項

以下は実績値ではなく、初回の実機評価に用いる案です。品質を満たせない場合は条件・代替案とともに改定し、都合のよい結果だけで完了扱いにしません。

| 項目 | 初期案・現在の制約 | 確定方法 |
| --- | --- | --- |
| 施設の近接判定 | 自動適用は半径500m以内（2026-11-10利用者指定）。圏外での候補表示の解除は550m（自動適用半径＋50m）・30秒 | 表示を保持していても500m圏外で自動適用しない。手動選択は距離にかかわらず優先。入館を証明する値ではない |
| 測位の鮮度・精度 | 取得から60秒以内、精度50m以内を自動適用の初期案 | 屋内・概略位置で保留と手動切替を検証 |

| ライブ注意の遅延 | 安定した対象で取得から表示までP95 1.5秒以内を仮目標 | 各条件30回以上測定し、未検出率・棄却率も併記 |
| 古い枠の扱い | 取得から2秒以上経過した結果は枠に採用しない案 | 対象を動かした際のずれと注意更新の両方を評価 |
| 継続動作 | まず5分間のカメラ利用で異常終了・操作不能がないこと | 実機の温度・メモリ・プレビューと操作を記録 |
| 静止画の入力 | 現行は60MB以下、長辺2400pxへ正規化 | 拡大しても必要な文字が読めるか、メモリと併せて評価 |
| 投稿文の上限 | 現行AI契約は先頭3,000のUTF-16コード単位を使用。画面上の文字数とは一致しない | UI文字数と絵文字を含む対象範囲を定義。無断の切り捨てを避ける |
| OCRのAI入力上限 | 連絡先・登録ワードのグループを優先し、残りを位置順に選ぶ。最大32読取、各180・合計1600のUTF-16コード単位 | 代替読取も予算内に数え、省略を表示。基本チェックは全読取を対象とする |
| 登録ワード数・長さ | 未確定 | 使い方と応答時間を踏まえて上限・入力案内を決める |
| AIの待ち時間・中止 | 未確定 | モデル初期化・推論時間を分けて測り、終了しない状態を防ぐ |
| 最低対応端末 | アプリ設定はiOS 16以上。AIとライブの対応保証範囲は別途 | iPhone 17 Proで先に検証し、古い端末へ一般化しない |
| 成果指標 | 見落とし率、修正完了率、不要な変更、所要時間、不要・重複警告 | validation-plan.md のチーム内比較を先に実施。現状未測定で、一般利用者や炎上減少への効果は断言しない |

優先して決める事項は、撮影中警告を含むP0範囲、最初の対象利用者、対応端末、ライブ表示品質、Cloud実行基盤の役割、大会カテゴリの適合です。推奨値や仮説は、ユーザー・チームが既に承認した事実として扱いません。

## 2026-11-08の履歴：企業モード・個人学習／復元の旧設計

企業プリセットと個人学習は端末内で継続します。以下の認証・復元・暗号化は当時の設計履歴です。2026-11-10の第7.3節を優先し、一般利用者のログイン・クラウド復元は追加予定から外します。既存コードがあることと、現在の提供範囲を区別してください。

- 企業モードでは種類別の必須非表示ルールを設定し、学習提案より優先する。端末内プリセットの試作であり、管理者による配布・改変防止は対象外。
- 個人学習は初期オフ。利用者が明示して記憶させた選択を、モード×種類×対象の集計として保存。写真・投稿文・OCR・人物IDは集計に保持しない。3回以上・75%以上の一致で提案し、自動投稿しない。オフ/リセット可能。
- Google/Appleログインによる設定復元を追加。設定・企業ルール・登録ワード・学習集計のみ送信可能。写真・投稿文・OCR・編集履歴・モデルは対象外。
- 暗号化はログインだけで復元できるサーバー管理方式。Cloud RunでAES-256-GCM、鍵はCloud KMS、Firestoreには暗号文。E2Eとは説明しない。
- 保存・復元・削除は明示操作。復元は全データ検証後に端末設定を一括置換。更新競合は無断上書きせず再取得を要求する。
- ユーザー指定により今回のクラウド作業はコード・接続設定まで。クラウドへの配置・請求先/IAM変更は行わない。実接続は未検証。
- 動画、複数画像、直接SNS投稿は今回の範囲外。

## 施設管理の委任確認 V17（2026-11-09追加）

V16以前の担当者連絡先の収集と、組織IDだけでの編集権限を置き換える。詳細は[施設管理権限](facility-access-v17.md)。担当者の氏名・電話・メール専用欄を設けず、GoogleログインのUIDと施設・役割・期限で認可する。認証基盤が保持するプロフィールまでゼロとは説明しない。

| ID | 要件・受け入れ条件 |
| --- | --- |
| FR-ACCESS-01 | 未確認の作成者は下書き保存のみ。施設責任者確認前の公開申請をAPIで拒否する |
| FR-ACCESS-02 | 運営が独立に公式窓口を確認し、24時間・1回限りの委任リンクを手動共有。委任先UIDは発行時に固定する |
| FR-ACCESS-03 | 確認済み責任者が施設ごとに担当者／責任者を招待・解除。同じ組織ID・リンク所持だけで担当者権限を与えない |
| FR-ACCESS-04 | 権限は最長90日、招待は発行者の期限内。解除・期限切れをAPIで再確認し、最後の責任者の解除を拒否する |
| FR-ACCESS-05 | ルールの運営承認と管理権限確認を分離。承認時も提出者の有効な施設権限を確認し、未承認版を公開しない |
| FR-ACCESS-06 | 個人連絡先専用欄は送信・保存・表示しない。既存専用欄を現行暗号化レジストリから削除し、自由入力・認証基盤・過去バックアップとは区別する |

### 2026-11-09追加：撮影後OCRとGemmaの併用改善

利用者指示により、撮影後の通常OCRへガンマ補正・2×2タイル拡大を追加し、Gemmaには写真自体から確認事項を提案する指示を与える。文字領域に複数の読取候補を保持して全候補をルール判定し、同じOCR領域を根拠とする確認項目を統合する。位置のないGemma指摘は写真全体への質問として手動範囲指定につなぐ。基本＋追加解析45秒、基本完了後の追加は最大10秒、Gemmaは別枠90秒。時間切れ・追加処理失敗でも取得済み結果を残し、基本完了後には「現在の結果で確認する」を選べる。ライブOCRは強化しない。初期設定の数値と精度改善の実測を区別し、4条件の比較で検証する。[設計](ocr-gemma-combined-design.md)／[実装・検証記録](ocr-gemma-implementation.md)。
