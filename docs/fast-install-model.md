# インストール軽量化とGemmaのWi-Fi自動取得

2026-11-09、利用者がインストールの遅さの解消を希望し、「初回起動後にWi-Fiで自動取得、完了までは基本チェック」を承認した。以前のGemma同梱方針より本方針を優先する。写真・文章・OCR・登録ワードをクラウドAIへ送らない方針は継続する。

## 利用者の体験

1. モデルを含まないアプリをインストールして開く。
2. AI補助がONなら、最初の画面を表示した後にWi-FiでGemmaの取得を始める。アカウント作成・モデルのファイル選択・USB転送は不要。
3. 準備中も、文字・顔・登録ワード・施設ルールの基本チェックと修正・書き出しを利用できる。Gemmaによる補助は準備完了後から使う。
4. 設定→端末内AIで、Wi-Fi待ち／取得中と進捗／検証中／利用可能／停止／失敗を確認する。停止・再開・再試行が可能。取得割合は小数1桁（例：50.0%）、取得済み容量／合計容量はMBで表示し、設定一覧からも確認できる。取得が終わっても検証中はAI利用可能と表示しない。AIをOFFにすると取得を停止する。保存済みのOFF設定と取得停止を維持する。
5. 同じモデルの検証済みキャッシュはアプリ更新時に再取得しない。初回のモデル取得量2,588,147,712 bytes自体を減らしたわけではない。

iPhoneではホームに戻る・画面ロック後もOS管理で取得する。OSによるアプリ終了にもバックグラウンドURLSessionで対応する。一方、利用者がアプリ一覧から上へ払って強制終了した場合、iOSは転送をキャンセルし、自動でアプリを再起動しない。利用者が開き直す必要がある（[Appleの仕様](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background%28withidentifier%3A%29)）。実機での背景取得完了を今回確認したわけではない。

初回からオフラインでGemmaを実行する構成ではない。準備が完了した後は、モデル配布元への接続なしでGemmaを実行する。停止・回線・OSの状態によって再開時に最初から取得し直す場合がある。

## 実装

- アセット定義から`.litertlm`を除去し、ステージング時のモデル取得・同梱準備を廃止。従来の同梱準備／USB転送スクリプトは不要な操作を案内する互換入口とする。
- Flutterの起動はモデルの取得・検証を待たない。ドメインにはモデル準備状態だけを置き、通信と保存はadapters／ネイティブ側に分離する。準備中の解析は基本チェックへ進み、取得の完了待ちで止めない。
- iOS：`PostCheckModelStore.swift`のバックグラウンドURLSessionを利用。アプリ起動時に同じセッション識別子へ再接続し、OSからの背景イベント完了通知も扱う。iOS 16の既存対象を維持し、iOS 26専用のApple-hosted asset packsは導入していない。
- `allowsCellularAccess`・`allowsExpensiveNetworkAccess`・`allowsConstrainedNetworkAccess`をfalseとし、Wi-Fi／接続条件が整うまで待つ。OS管理のバックグラウンド通信であり、強制終了・省データモード・容量不足等でも必ず即時再開できると保証しない。
- Android：Wi-Fi限定・ローミング／従量制接続不可のDownloadManagerへ接続。OSが取得を継続し、アプリから状態を確認したときに検証する。Android SDKが本環境にないため、今回Androidのビルド・実機は未検証。
- 公開された固定モデルURLへのGETだけを行う。Flutterからダウンローダへ渡す引数に、写真・投稿文・OCR・登録ワード・任意URLを含めない。HTTPの生エラーも画面やアプリログへ出さない。モデル配布元には通常のIP等の通信メタデータは発生する。
- サイズと固定SHA-256をストリーム読み込みで検証する。HTTP失敗、途中ファイル、不正サイズ、ダイジェスト不一致は利用可能にしない。検証完了したファイルだけを推論パスへ渡す。2.59GBの重みをDartや一括Dataバッファへ読み込まない。
- 検証済みファイルは専用保存先に置き、検証値・更新時刻・サイズでキャッシュを確認する。モデル用フォルダはOSバックアップ対象外。停止状態も保存し、次回起動の自動取得で勝手に再開しない。
- ライセンス本文とアプリ内ライセンス登録を維持。旧版で手動追加したファイルや個人の下書きを自動削除しない。

モデル：[Gemma 4 E2B公開ファイル](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/blob/main/gemma-4-E2B-it.litertlm)、SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`。

Apple：[バックグラウンドダウンロード](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)。Android：[DownloadManager.Request](https://developer.android.com/reference/android/app/DownloadManager.Request)。

## 数値進捗の追加（2026-11-09）

設定一覧と端末内AI画面に、取得割合（小数1桁）と取得済みMB／合計MBを追加。2秒周期の状態更新と復帰時の更新を継承し、停止中も現在の取得量を表示する。未完了の値を丸めて100%にしない。全バイト取得後は100.0%と検証中を表示し、検証が完了した後に利用可能へ切り替える。端末内AI画面へ、ホーム／ロックと強制終了の違いも案内する。

今回のFlutter静的チェックと全118テストが成功。既存の連携テストを拡張し、設定一覧の数値、2秒後の進捗更新、停止中の数値保持、99.9%→100.0%検証中→利用可能を確認。UIキャプチャは[日本語](../output/postcheck-model-progress/ja.png)・[英語](../output/postcheck-model-progress/en.png)。架空の50%取得状態を描画したもので、実端末のダウンロード実測ではない。ネイティブの取得方式は今回変更していない。
