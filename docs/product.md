## 何をするアプリか

SNSに投稿する写真と文章を公開前に確認し、見落としやすい箇所について「ここ、公開して大丈夫？」と問いかけます。投稿者が、隠す・直す・そのまま使うを選び、修正後の内容を再チェックして保存・共有します。

目的は、意図せず公開した名前や連絡先、背景資料、告知前の情報などから生まれるトラブルを減らすことです。「炎上するか」を点数で予言することはMVPの機能にしません。

## 想定する利用者と場面

最初の検証対象は、サークル・学生団体などでイベント写真と投稿文を作るSNS担当者に絞ります。これは対象仮説であり、需要確認済みではありません。たとえば、集合写真に名札や背景モニターが写っていたり、イベント報告の文章に告知前の企画へ触れる一文が含まれていたりする場面です。

この対象と課題は企画上の仮説です。利用者へのヒアリングや、見落としをどれだけ減らせるかの効果検証はこれから行います。

## 場所に合わせて使える体験

端末GPSとPostCheckに登録された施設座標を照合し、近くの施設の公開ルールを自動取得して初期ONにします。「近くの施設：〇〇（推定）」と表示し、入っていなければOFF、合っていればそのまま使えます。施設が違う場合だけ変更します。

施設未登録・ルールなし・位置不明・OFFでも、顔・連絡先などの基本チェックは継続。Google Mapsは地図表示に使い、Places APIは使いません。ルールは組織が別Webで登録して承認された自前データです。一般利用はアカウント不要を基本方針とし、ログイン情報を収集しません。Google／Appleログインと個人設定のクラウド保存・復元は追加予定に含めません。設定・登録ワードは端末内に保存し、機種変更・アプリ削除時の引き継ぎは提供しません。施設管理Webの認証・認可は維持します。組織限定配信は後続フェーズです。

位置情報は入館や部屋を証明しません。既存写真へ現在地を無断適用せず、撮影後の下書きは移動だけで施設ルールを変更しません。

## MVPの体験

1. カメラをかざすと、文字・連絡先・登録ワード・顔等の写り込みを枠と短い注意で知らせる。構図を調整して撮影し、写真を採用する。写真の選択や文章だけの入力も利用できる。
2. 端末内の文字・顔の位置・連絡先・登録ワード等を確認する。モデルがあれば写真と文章の文脈も補助する。
3. 写り込みや文章に対応した確認候補と、短い問いかけを表示する。
4. 投稿者が候補ごとに判断し、必要な箇所を不透明な黒塗りで隠す、文章を編集する。
5. 修正後を再チェックし、実際に書き出す写真と文章を確認する。
6. 保存・共有先を選ぶ。SNSへの投稿は利用者が行う。

## MVPに含める内容

| 領域 | 内容 |
| --- | --- |
| 入力 | 写真ライブラリ、カメラ、投稿文、架空データのサンプル |
| 撮影中の気づき | 文字・連絡先・登録ワード・顔の位置への端末内の注意表示。実装あり。品質・条件別の検証は継続 |
| 場所ルール | 近くの登録施設を自動候補にし公開ルールを適用。利用者のOFF・変更を優先。実装・架空位置テスト済み。実GPSの現場評価は未了 |
| 基本チェック | 日本語OCR、顔の位置、メール・電話番号、今後の告知を示す語、登録ワード |
| AI補助 | 初回起動後にWi-Fiで自動取得するGemmaの画像・文章理解による確認候補。手動追加不要。準備中・実行不可でも基本チェックを利用可能 |
| 利用者の判断 | 確認理由、対象箇所、「問題なし／隠す／戻す」、手動範囲指定 |
| 修正と出力 | 画像の黒塗り、文章の修正、再チェック、PNGと文章の共有 |

最新のV4全16画面・状態は、写真選択を主な入口に、写真と下部カードで確認・修正する構成です。撮影・写真選択・カメラ権限不許可からの復帰も含めています。すべての画面案が現行アプリへ実装済みという意味ではありません。

## 判断とデータの方針

- 指摘は確認のきっかけ。人物を識別したり、掲載の同意を自動で判断したりしない。
- 「安全です」「公開OK」「検出率100%」と断定しない。見落としや誤検出がある前提で、最終判断を利用者に残す。
- 写真・文章の解析は端末内。投稿内容をクラウドAIへ自動送信しない。
- アプリ取得・更新、公開モデルのWi-Fi取得・共有操作・SDK診断通信は別途存在する。通信が一切ないという説明はしない。
- 端末内の一時データ・設定・モデル・共有用ファイルの扱いは[アプリREADME](../postcheck/README.md#データの扱い)に従う。

## 拡張候補

SNS別アダプター、共有拡張、社内ルールの意味検索は将来の候補です。誹謗中傷・差別表現などの網羅的な判定や、炎上予測の精度保証も現在の実装として説明しません。まず、写真の写り込みと公開タイミングの確認を、短い操作で完了できる体験に集中します。
