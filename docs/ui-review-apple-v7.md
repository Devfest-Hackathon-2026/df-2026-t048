# PostCheck UIレビュー・Appleスタイルへの修正（V7）

更新日：2026-11-08。対象は現在利用できるモバイルアプリの画面。ソースコード、Flutterの描画キャプチャ、操作テストに基づく専門家レビューであり、利用者実験の結果ではない。

## 結論

修正前は、写真を扱うアプリなのに説明・設定・診断情報が主役になっていた。機能は揃っていても「開けば迷わず使える」構成ではなく、開発用の操作画面に近い。透明なボタンを足すだけでは改善しない。情報の優先順位、操作の配置、状態の伝え方から変更する。

ユーザーの最新指定により、モバイルの見た目はAppleスタイルを優先する。以前のMATRAICE／Notionの配色・角丸・書体規則はモバイルの現行基準ではない。写真中心の確認フローと施設ルールの仕様は継承する。組織管理Webと未公開のクラウド復元画面は今回の再設計対象外。

「説明を減らす」は重要な確認条件を消すことではない。撮影不可、企業モードで必ず隠す対象、未確認件数、古いルール、ライブラリ写真への施設適用確認は残す。安全保証や炎上確率は表示しない。

## デザイン・実装方針

- 背景はグループ化された淡いグレー、内容は白、強調は青。写真と本文には透明効果を重ねない。
- 大きい見出し・余白と、短い操作ラベルを使う。詳細はシートまたは設定の下位画面へ。
- Glassはナビゲーション、下部の主要操作、カメラ上の浮いたボタン・施設情報に限定する。Appleもコンテンツと操作層を分ける材料の使い方を案内している。[Apple HIG: Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
- Flutterを維持し、`apple_components.dart`からiOSのPlatform Viewへ接続。iOS 26以降はUIKitの`UIGlassEffect`、以前は`UIBlurEffect`。他プラットフォームと描画テストではFlutterのぼかし表現を使用する。[UIGlassEffect](https://developer.apple.com/documentation/uikit/uiglasseffect)
- iOSの「透明度を下げる」は不透明背景へ切り替える。Flutter側の高コントラスト・アクセシビリティ指定でも透過を抑える。通常画面全体のダークモードは未追加。
- 確認ロジックとSDKの分離、5mを目安とする前景位置更新、手動で外した施設ルールの優先、修正後の再チェック・書き出し制限は維持する。

主な変更先：`presentation/app_theme.dart`、`apple_components.dart`、`home_page.dart`、`settings_page.dart`、`nearby_card.dart`、`venue_page.dart`、`mask_editor.dart`、`adapters/live_camera_page.dart`、`ios/Runner/AppDelegate.swift`。
