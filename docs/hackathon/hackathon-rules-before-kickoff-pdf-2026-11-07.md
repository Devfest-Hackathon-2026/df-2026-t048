**2026年11月7日のユーザー共有によると、Geminiの使用は必須ではない。** 以前の「必須」という整理を訂正し、Geminiを含まない構成も検討対象にする。

Gemini APIを呼ぶだけではGoogle Cloud実行基盤の要件を満たさない。下記の指定実行基盤を最低1つ使用する。他社LLMの併用自体は禁止されていないが、Google技術の評価にはならない。

## 2. 失格・審査対象外につながる重要ルール

### 開発開始前に本番ソースコードを書かない

11月5日10:00より前は、IaC、CI/CD、フレームワーク初期化などの実装も禁止。事前PoCのコード流用も禁止。

### 指定5カテゴリのどれかに属する

カテゴリ外のプロダクトは審査対象外。

1. 医療・福祉
2. 観光
3. 教育
4. エンターテインメント
5. クリエイティブ

### 指定Google Cloud実行基盤を使用する

以下から最低1つ必要。Gemini APIを呼ぶだけでは基盤要件を満たさない。

1. App Engine
2. Compute Engine
3. Google Kubernetes Engine（GKE）
4. Cloud Run
5. Firebase App Hosting
6. Firebase Hosting

構成例：Three.jsで3D世界を作り、Firebase Hostingで配信し、GeminiをVertex AI経由で利用する。

### Google技術をプロダクトの中核に使う

Google技術をプロダクトの価値に結びつけて活用し、選定理由を説明する。Gemini自体は必須ではないとの最新共有がある。Google Cloud実行基盤の条件は別項目として確認する。

### 提出物と公開権限を守る

指定リポジトリ・説明資料・動画等を提出。Google Driveフォルダは「リンクを知っている全員が閲覧できる」設定にする。

### チーム全員がDiscordに参加する

11月4日23:59までに全員参加する。運営からの連絡はDiscordで確認する。

## 3. 開発前にできること・できないこと

以下は11月5日10:00より前の制限。

| 作業 | 可否 |

| FigmaなどでのUIデザイン | 可能 |

| 本番用IaC・CI/CD構築 | 禁止 |

## 4. 審査基準：8項目×3点＝24点満点

各項目0〜3点の4段階評価。以下の説明は、共有された審査基準をブレスト用に整理したもの。

| 分野 | 審査項目 | 満点 |
| --- | --- | ---: |
| Google技術 | ① 中核として機能しているか | 3 |
| Google技術 | ② 技術選定の理由を説明できるか | 3 |
| 完成度 | ③ 一連の操作が最後まで動くか | 3 |
| 完成度 | ④ UI・UXが使いやすいか | 3 |
| 完成度 | ⑤ 安全性・拡張性・保守性を考えた設計か | 3 |
| 社会課題 | ⑥ 誰のどんな課題か具体的か | 3 |
| 社会課題 | ⑦ その解決策が実際に有効か | 3 |
| ピッチ | ⑧ 説明とデモが伝わり、印象に残るか | 3 |
| 合計 | | **24** |

### ブレストでの判断ポイント

技術力だけでなく、社会課題への解決力と完成度が重要。「なぜGoogle技術が必要なのか」「なぜその課題を解決するのか」を説明できない案は、実装が派手でも評価を落とす可能性がある。
