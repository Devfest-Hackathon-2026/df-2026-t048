# 管理画面のルール入力を確認項目だけに整理

2026-11-10の利用者指示。「この施設で必ず指摘する項目」だけをStep 2に残し、アプリと互換にする。

- Step 1の申請名・施設名・住所・位置・公式サイトは継続する。Step 2は12項目のON/OFFのみ。イベント・可否・条件・確認ワード・日時・原文・URL・画像・翻訳・配信範囲の入力欄は撤去。
- 項目のIDと日本語名を共通Dart契約へ集約。モバイルの`CheckTarget`との一致をテストし、既存の`checkTargets`配列で保存・配信する。別形式への移行はない。
- 新規施設は全項目OFFが初期値。全OFFも許容し、施設は追加の指摘を行わない。ONにした項目は利用者設定のOFFより優先し、利用者がONにしている項目を施設側のOFFで抑制しない。
- 新規の項目指定だけのルールは、原文・参考URLを入力せず保存・申請できる。住所・施設管理の委任確認・公開内容の確認・運営承認は引き続き必要。既存の詳細ルールを伴う申請では原文・参照元の検証を維持する。
- 既存施設の原文・翻訳・条件・ワード・期限・配信範囲などは保存時に保持する。今回の画面整理を理由に既存レコードを削除・公開・再承認する処理はない。
- 最終確認は施設情報と指摘する項目に整理。アプリも項目指定だけの施設では同じ項目一覧を表示し、存在しない原文・翻訳の入力を案内しない。既存の詳細ルールの表示・意味照合は継続する。

## 検証

- Go: `go test -race ./...`・`go vet ./...`成功。原文・参照元なしの項目指定（全OFFを含む）の保存→委任確認→申請→承認→公開を検証。
- 管理Web: 静的解析・12テスト成功。Step 2に12チェックボックスだけを表示し、項目の自動保存、既存詳細・翻訳の保持、隠した項目を入力せず最終申請できることを確認。
- モバイル: 静的解析・全270テスト成功。日英の項目表示、原文なしの項目指定ルール、IDと表示名の一致、施設のONが利用者のOFFに優先することを確認。
- 共通Dart: 静的解析・7テスト成功。
- 架空データだけのローカルGo APIとDartクライアントで、項目指定だけの保存→委任確認→申請→承認→公開取得→停止が成功。未確認の担当者の申請拒否も継続。
- Webリリースビルド成功。API・Hostingの反映結果、Chromeの操作確認は配布記録へ追記する。
- TestFlightは更新していない。モバイルの新表示・新設定を利用するには対応する最新版が必要。実モデルの精度を今回の契約・画面テストの結果として扱わない。
